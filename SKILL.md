# mstack

mstack is Miracle's stack by 0xmiracle, built on [pstack](https://github.com/cursor/plugins/tree/main/pstack) by Lauren Tan (poteto). MIT licensed, see `LICENSE`. Its 57 skills are bundled in this folder. Only this file is installed as a claude.ai skill. The rest are read from disk when a step needs them.

mstack is opt-in, like pstack's poteto-mode. It is rigorous and built for large work: features that cross modules, migrations, hard bugs, long unattended runs. On a small task it spends many tokens and runs slowly. The user decides when to use it by typing `/mstack`.

## Start here

1. Note this file's folder as `<mstack>`. The Skill tool printed it as the base directory.
2. Read `<mstack>/docs/harness/claude-ai.md` once per session. The bundled skills were written for Cursor, and that file maps every Cursor name to what claude.ai offers, including the all-Claude model table.
3. Route the request.
   - The user named a bundled skill below (`/how ...`, "unslop this", "run interrogate on it") → read `<mstack>/skills/<name>/INSTRUCTIONS.md` and follow it.
   - Anything else, including a bare `/mstack` or `/miracle-mode` → read `<mstack>/skills/miracle-mode/INSTRUCTIONS.md` in full and follow it. It picks the playbook and calls the other skills as its steps need them.
   - The user is new or unsure what to call → `<mstack>/skills/miracle-help/INSTRUCTIONS.md`.

Every bundled skill links to its neighbours with relative paths such as `../why/INSTRUCTIONS.md`. Resolve them from the linking file's own folder.
